# Tizen app host

Packages the agent runtime as a Tizen web app (`.wgt`).

## Build & install (tizen-core `tz`)

**Tizen Studio is EOL.** Use the **Tizen VS Code extension**, which ships the
`tz` CLI — it replaces `tizen build-web` / `tizen package`, Certificate Manager
and Emulator Manager.

```bash
# One-time: author certificate + signing profile. This BUILDS a signed .wgt;
# installing on a Samsung TV or its emulator additionally needs a Samsung
# certificate — see docs/EMULATOR_SETUP.md §A2.
tz cert -n "Your Name" -p <password> -f my-dev
tz security-profiles add -n my-dev -A -a <author.p12> -p <password> \
  -d <tizen-core>/certificates/distributor/tizen_public_signer.p12 \
  -P tizenpkcs12passfordsigner

# Build + sign, from the repo root (bundles the runtime, generates the icon if
# missing, then tz build + tz pack):
pnpm package:tizen               # → Debug/tizen-app.wgt

# Install on a target (MTK/NVT Tizen TV in Developer Mode, or an emulator)
sdb connect <TV_IP>
sdb devices                      # nothing listed = nothing to install to
tz install -p Debug/tizen-app.wgt    # -p is the package PATH
tz run -p tvaiagent                  # -p is the package ID from config.xml,
                                     #    not the application id
```

Three certificate tiers, and mixing them up costs an afternoon: a locally
generated Tizen cert (`tz cert`) **builds** a signed package; a **Samsung**
certificate (Certificate Manager, free Samsung account) is required to **install**
on a Samsung TV or its emulator; a Samsung **partner** certificate is only for the
privileged capabilities the POC defers (input switching, standby). See
[`docs/EMULATOR_SETUP.md`](../../docs/EMULATOR_SETUP.md) §A2.

## Notes
- `tizen_web_project.yaml` is the project manifest `tz` reads. `node_modules` is
  excluded there on purpose: pnpm links workspace dependencies as junctions and
  the packager fails on them with "Incorrect function".
- `icon.png` is generated by `pnpm icon` (`tools/make-icon.mjs`) — placeholder
  artwork, drawn in code so it can be regenerated at any size.
- Bring-up flags work the same as on AOSP: `?diag` (capability probe, `&writes`
  to exercise volume set/restore), `?llm=…&model=…` to repoint a packaged app at
  another endpoint without rebuilding, `?confirm=auto|deny` for automated runs.
  The `?diag` report is also written to the console, so the Web Inspector gives
  you copyable text.

See `docs/platform/tizen-bringup.md` for MTK/NVT specifics.
